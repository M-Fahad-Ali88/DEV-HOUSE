DETERMINISTIC TEST EXECUTION WITH PYTEST

Deterministic testing means a test always produces the same output when given the same input and environment. A good test should never randomly pass or fail. Pytest provides powerful tools like fixtures, parameterization, and configuration files to make testing reliable, organized, and scalable.

1. PYTEST
Definition

Pytest is one of the most popular Python testing frameworks used to write, organize, and execute automated tests.

Instead of manually running your code every time you make changes, pytest automatically checks whether your program still works correctly.

Example
def add(a, b):
    return a + b

def test_add():
    assert add(2, 3) == 5

Run:

pytest

Output

1 passed
2. DETERMINISTIC TESTING
Definition

A deterministic test always produces the same result every time it runs.

If a test passes today, it should also pass tomorrow unless the code changes.

Good Example
assert 5 + 5 == 10

This always passes.

Bad Example
import random

assert random.randint(1,10) == 5

Sometimes passes.
Sometimes fails.

This is non-deterministic.

4. PYTEST.INI
Definition

pytest.ini stores global pytest settings.

Instead of writing long commands every time, configuration is stored once.

Example

[pytest]
testpaths = tests
python_files = test_*.py

Now pytest automatically looks inside

tests/

for files beginning with

test_
5. STRICT WARNING FLAGS

Sometimes your code produces warnings.

Example

DeprecationWarning

Normally pytest shows the warning but still passes.

Strict mode converts warnings into failures.

Example

[pytest]
filterwarnings =
    error

Now

DeprecationWarning

becomes

FAILED

This helps detect future problems early.

6. STRICT MARKER VALIDATION

Pytest allows custom markers.

Example

@pytest.mark.database

If you accidentally write

@pytest.mark.databse

(pytest typo)

Without strict markers

No error

With strict markers

Unknown marker

This prevents spelling mistakes.

7. TEST DISCOVERY

Pytest automatically finds tests.

It searches files named

test_*.py

or

*_test.py

Inside those files it executes

def test_login():

Functions beginning with

test_

No manual registration is required.

8. FIXTURES
Definition

Fixtures prepare resources before a test and clean them afterward.

Instead of writing setup code repeatedly, write it once.

Without fixture

def test1():
    db = Database()

def test2():
    db = Database()

Repeated code.

With fixture

@pytest.fixture
def db():
    return Database()

Now every test simply requests

def test_user(db):

Pytest injects it automatically.

15. YIELD FIXTURE

Pytest uses yield to separate setup and teardown.

Example

@pytest.fixture
def db():
    print("Connect")
    yield
    print("Disconnect")

Execution

Connect

↓

Run test

↓

Disconnect

Everything before

yield

is setup.

Everything after

yield

is teardown.

16. @pytest.mark.parametrize

Instead of writing many similar tests, parameterization runs one test multiple times.

Without parameterization

def test1():
    assert add(1,2)==3

def test2():
    assert add(2,3)==5

def test3():
    assert add(4,5)==9

With parameterization

@pytest.mark.parametrize(
    "a,b,result",
    [
        (1,2,3),
        (2,3,5),
        (4,5,9)
    ]
)

Much shorter.

Cleaner.

Reusable.

21. TEST ISOLATION

Every test should be independent.

Good Example

Tests should never depend on execution order.
