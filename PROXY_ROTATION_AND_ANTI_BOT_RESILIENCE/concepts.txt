1. Theoretical Focus

Is task mein hum ye samajh rahe hain ke websites automated bots ko kaise identify aur control karti hain, aur scraper apni requests ko properly manage kaise kar sakta hai.

Browser Fingerprinting

Browser fingerprinting ka matlab hai website browser ke different characteristics ko dekh kar uski unique identity/profile banana.

For example:

User-Agent
Accept-Language
Screen/browser information
Browser capabilities
Kuch network-level characteristics

Agar har request bilkul same pattern follow kare, website ko automation ka indication mil sakta hai.

TLS / JA3 Signature

Jab browser/server ke darmiyan HTTPS connection establish hota hai to TLS handshake hota hai.

JA3 ek technique hai jo TLS handshake ki kuch characteristics se client fingerprint create karti hai.

Simple words mein:

Browser / Client
       ↓
   TLS Handshake
       ↓
JA3 Fingerprint
       ↓
Server ko client ka pattern pata chal sakta hai

Yani sirf User-Agent change karna hamesha enough nahi hota; network-level characteristics bhi identify ki ja sakti hain.

IP Blocking

Agar ek IP address se bohat zyada requests aayen ya server ko suspicious traffic mile, server us IP ko:

temporarily block
rate-limit
ya permanently restrict

kar sakta hai.

Example:

IP → 192.168.x.x
      ↓
1000 requests
      ↓
Server detects excessive traffic
      ↓
429 Too Many Requests
      ↓
IP temporarily restricted
User-Agent Pooling

Normally agar scraper har request mein same User-Agent use kare:

Request 1 → Chrome UA
Request 2 → Chrome UA
Request 3 → Chrome UA
Request 4 → Chrome UA

to pattern consistent rehta hai.

User-Agent pool mein multiple predefined User-Agents maintain kiye ja sakte hain:

user_agents = [
    "Mozilla/5.0 ...",
    "Mozilla/5.0 ...",
    "Mozilla/5.0 ..."
]

Middleware request ke liye pool se appropriate User-Agent select karta hai.

Distributed Proxy Rotation

Proxy ka basic concept:

Scraper
   ↓
Proxy
   ↓
Website

Agar multiple proxies available hon:

             ┌── Proxy A
             │
Scraper ─────┼── Proxy B
             │
             ├── Proxy C
             │
             └── Proxy D

to requests ko available endpoints ke through distribute kiya ja sakta hai.

TLS Handshake simple words mein woh process hai jisme browser aur server HTTPS connection start karne se pehle ek secure connection establish karte hain.

Example:

Tumhara Browser
       ↓
   "Hello Server!"
       ↓
     Server
       ↓
"Hello Browser!"
       ↓
Security information exchange
       ↓
Encryption keys establish
       ↓
🔒 Secure HTTPS Connection
Simple example

Jab tum browser mein:

https://example.com

open karte ho, browser ko server ke saath encrypted communication establish karni hoti hai.

TLS handshake roughly ye kaam karta hai:

Client Hello → Browser server ko batata hai ke woh TLS connection establish karna chahta hai.
Server Hello → Server suitable security settings select karta hai.
Certificate → Server apni identity prove karne ke liye TLS certificate provide karta hai.
Key Exchange → Browser aur server secure encryption keys establish karte hain.
Secure Communication → Ab actual data encrypted form mein exchange hota hai.
JA3 se connection

Tumhare current task mein JA3 isi process se related hai.

TLS handshake mein client kuch specific characteristics/features present karta hai. In characteristics ko use karke ek TLS fingerprint banaya ja sakta hai, jise JA3 fingerprint kaha jata hai.

Browser
   ↓
TLS Handshake
   ↓
TLS Characteristics
   ↓
JA3 Fingerprint
   ↓
Server

Isliye sirf User-Agent change karne se client ka complete network identity pattern necessarily change nahi hota.

Short definition:

TLS handshake = Browser aur server ke darmiyan secure HTTPS communication establish karne ka initial process.

Task 2 — Human-Like Interaction Behaviors

Is task ka main purpose hai browser automation mein fixed/deterministic behavior ke bajaye variable interaction patterns model karna.

1. Randomized Delay Jitter

Normally agar automation mein hum likhein:

time.sleep(2)

to har dafa exactly 2 seconds wait hoga.

Hamare code mein:

delay = random.uniform(
    self.min_delay,
    self.max_delay
)

Aur values hain:

self.min_delay = 0.8
self.max_delay = 2.5

Iska matlab program 0.8 se 2.5 seconds ke darmiyan koi random value select karega.

Tumhare run mein:

Delay: 1.91 seconds

phir:

Delay: 2.50 seconds

Dono delays different thay.

Concept:

Randomized delay jitter = fixed waiting time ke bajaye variable waiting time use karna.

2. Dynamic Mouse Trajectory

Agar mouse ko directly:

Start ──────────────────> End

move karaya jaye, to movement completely deterministic hogi.

Hamare code mein:

steps = random.randint(8, 15)

Yeh decide karta hai ke mouse movement ko kitne intermediate steps mein divide karna hai.

Tumhare run mein:

Mouse movement steps: 13

Yani mouse ne start aur end position ke darmiyan 13 intermediate movements use kiye.

progress kya karta hai?

Code:

progress = step / steps

Ye calculate karta hai ke mouse apni journey ka kitna portion complete kar chuka hai.

Example:

Agar total steps 10 hain:

Step 1  → 10%
Step 2  → 20%
Step 3  → 30%
...
Step 10 → 100%

Phir:

current_x = start_x + (end_x - start_x) * progress
current_y = start_y + (end_y - start_y) * progress

start aur end coordinates ke beech current position calculate hoti hai.

Small Random Variation

Phir code:

current_x += random.uniform(-3, 3)
current_y += random.uniform(-3, 3)

mouse ki position mein small random variation add karta hai.

Yani movement perfectly identical nahi rehti.

Iske baad:

page.mouse.move(current_x, current_y)

Playwright browser ke mouse ko us calculated position par move karta hai.

with sync_playwright() as p:

Playwright automation environment start karta hai.

    headless=False
)

Chromium launch hota hai.

headless=False ka matlab browser visible hota hai.

Phir:

page = browser.new_page()

new browser page/tab create hota hai.

Aur:

page.goto("https://example.com")

website open karta hai.

Task 1 mein humne proxy pool banaya tha, aur Task 2 mein browser interaction behavior handle kiya tha.

Task 3 ka purpose hai:

Proxy pool ke andar har proxy ki health check karna aur jo proxy kaam nahi kar raha ya rate-limited hai usko active pool se remove karna.

Sabse pehle:

self.proxies = [
    "http://proxy1.example.com:8080",

]

Conceptually:

Proxy 1
Proxy 2
Proxy 3

2. Active Proxy Pool
self.active_proxies = self.proxies.copy()

Active Proxies:

Proxy 1
Proxy 2
Proxy 3

.copy() original list ki copy banata hai.

Iska benefit ye hai ke hum active_proxies ko modify kar sakte hain without directly modifying self.proxies.

3. Unhealthy Proxies
self.unhealthy_proxies = {}

Ye ek dictionary hai jahan hum problematic proxies store karenge.

Example:

Proxy 2 → cooldown
Proxy 3 → unhealthy
4. check_proxy()
def check_proxy(self, proxy):

Ye function ek particular proxy ki health check karta hai.

Demo mein:

status = random.choice([200, 200, 200, 429, 500])

Randomly ek status select hota hai.

Possible values:

200
429
500
200
if status == 200:
    return "healthy"

Matlab proxy healthy hai.

429
if status == 429:
    return "rate_limited"

429 ka meaning hai Too Many Requests.

Hamare system mein iska matlab:

Proxy ko temporarily active pool se remove karo aur cooldown state mein rakho.

500

Agar 200 ya 429 nahi hai:

return "unhealthy"

Yahan 500 ko unhealthy treat kiya gaya hai.

5. monitor_proxy()

Ye Task 3 ka important function hai.

def monitor_proxy(self, proxy):

Iska kaam hai:

Proxy ko check karna aur uski status ke according proxy pool update karna.

Sabse pehle:

status = self.check_proxy(proxy)

Yani check_proxy() se status obtain hota hai.

Healthy Proxy

Agar:

status = healthy

to:

if proxy not in self.active_proxies:
    self.active_proxies.append(proxy)

Proxy active pool mein ensure kiya jata hai.

Aur:

self.unhealthy_proxies.pop(proxy, None)

Agar proxy pehle unhealthy list mein tha, to usko remove kar dete hain.

So:

Unhealthy → Healthy

hone par proxy wapas active pool mein aa sakta hai.

6. Rate-Limited Proxy

Agar:

status = rate_limited

to:

if proxy in self.active_proxies:
    self.active_proxies.remove(proxy)

Proxy active pool se remove hota hai.

Phir:

self.unhealthy_proxies[proxy] = "cooldown"

Uski state store hoti hai:

Proxy 2 → cooldown

Yani ye proxy temporarily inactive hai.

7. Unhealthy Proxy

Agar proxy unhealthy hai:

if proxy in self.active_proxies:
    self.active_proxies.remove(proxy)

Isko active pool se remove kar dete hain.

Phir:

self.unhealthy_proxies[proxy] = "unhealthy"

Dictionary mein record:

Proxy 3 → unhealthy
8. run_health_checks()

Ab ye function poore proxy pool ko check karta hai.

for proxy in self.proxies:
    self.monitor_proxy(proxy)

Agar 3 proxies hain:

Proxy 1 → Check
Proxy 2 → Check
Proxy 3 → Check

Har proxy ke liye monitor_proxy() call hota hai.

time.sleep(1)
time.sleep(1)

Har health check ke darmiyan 1 second ka pause hai.

Ye demo mein checks ko readable banata hai aur immediately sequential calls ko avoid karta hai.

9. Final Active Proxies

End mein:

Agar available hain:

Active Proxies:
- Proxy 1
- Proxy 3

10. Inactive Proxies

Phir:

for proxy, reason in self.unhealthy_proxies.items():

Example:

Inactive Proxies:

- Proxy 2 -> cooldown
