Theoretical Focus
1. High-Throughput Crawling Architectures

High-throughput crawling uses asynchronous operations and concurrency to handle many web requests efficiently.
Pagination can be managed through queues or iteration instead of deep recursion.

2. Item Pipelines

Item pipelines process scraped data before it reaches the database or storage layer.
They can clean, transform, validate, and filter raw data.

3. Middleware Extensions

Middleware provides reusable logic for processing requests and responses during crawling.
It can handle retries, headers, rate limiting, authentication, and error responses.

4. Stateful Scraping Sessions

Stateful sessions maintain information such as cookies, authentication, and session IDs across requests.
This allows the crawler to maintain continuity when accessing multiple pages.

Pagination means dividing a large amount of content into multiple pages instead of showing everything on one page.

For example, an online store might have:

/products?page=1
/products?page=2
/products?page=3
/products?page=4

A crawler processes Page 1 → Page 2 → Page 3 → Page 4 to collect all the data.

So, simply: Pagination = moving through multiple pages of the same type of content.

Task 2 — Task2RetryBackoff.py

Contains automated retries, exponential backoff, timeout handling, and HTTP 429/503 handling.

fetch_with_retry()
Sends the HTTP request and checks whether it succeeds or encounters a temporary error.

Retry mechanism
If there is a network error, timeout, 429, or 503, the request is attempted again.

Exponential backoff
The waiting time increases after each failed attempt: 1s → 2s → 4s.

main()
Creates the HTTP session and starts the retry-enabled request.

Flow:

main()
  ↓
fetch_with_retry()
  ↓
HTTP Request
  ↓
Success → Return Data
  ↓
Failure → Wait → Retry
