DECLARATIVE RUNTIME VALIDATION USING PYDANTIC V2
MAIN MOTIVE OF THIS TOPIC

The main purpose of Declarative Runtime Validation using Pydantic v2 is to ensure that incoming data is correct, clean, secure, and follows predefined rules before it is used by an application. Instead of manually checking every field, developers declare validation rules inside models, and Pydantic automatically validates data at runtime.

THEORETICAL CONCEPTS
1. Runtime Validation
Definition

Runtime validation is the process of checking whether data is valid while the program is running.

Purpose
Prevent invalid data from entering the application.
Detect incorrect input immediately.
Improve application reliability.
Reduce unexpected runtime errors.
2. Declarative Validation
Definition

Declarative validation means describing validation rules inside a model instead of writing manual checking code.

Rather than writing many if statements, developers declare rules using fields, types, and validators.

Advantages
Cleaner code
Easier maintenance
Automatic validation
Better readability

Definition

BaseModel is the fundamental class in Pydantic used to define the structure of expected data.

It acts as a blueprint describing:

required fields
optional fields
nested objects
data types
validation rules
2. Data Schema

A schema is a formal description of data.

It specifies

field names
field types
required values
optional values
nested structures

Example concept

User
 ├── name
 ├── age
 ├── email
 └── address
        ├── city
        ├── country
        └── zipcode
3. Nested JSON

Nested JSON contains objects inside objects.

Example concept

User
 ├── Personal Information
 ├── Address
 │      ├── City
 │      ├── Country
 │      └── Zip
 └── Company
        ├── Name
        └── Department

Large applications frequently receive deeply nested JSON.

Security settings

TASK 2
IMPLEMENT CUSTOM @field_validator AND @model_validator FUNCTIONS TO HANDLE SANITIZATION AND BUSINESS-LOGIC RULES
1. Validators

Validators are special functions executed automatically during validation.

Their job is to

inspect data
clean data
reject invalid values
enforce business rules
2. @field_validator
Definition

A field validator validates one field at a time.

It runs before or after normal validation depending on configuration.

Responsibilities
Remove whitespace
Normalize text
Validate format
Check ranges
Convert values
Reject invalid input
3. Field Sanitization

Sanitization means cleaning data before storing it.

Examples

Remove leading spaces
Remove trailing spaces
Convert uppercase to lowercase
Remove unwanted characters
Normalize formatting

Purpose

Keep database consistent
Prevent duplicate records
Improve searching
4. Email Normalization

Email normalization ensures all emails follow one standard format.

Typical operations

lowercase conversion
trimming whitespace
removing accidental spaces

Purpose

ABC@EMAIL.COM

and

abc@email.com

become identical.
5. Phone Number Validation

Phone validation ensures numbers satisfy predefined rules.

Typical checks

Correct length
Numeric characters
Country code
Allowed symbols
Formatting
6. @model_validator
Definition

A model validator validates the entire model after individual fields are validated.

It has access to every field simultaneously.

7. Cross-field Validation

Some rules depend on multiple fields.

Examples

Password equals confirmation
Start date before end date
Age matches birth date
Country matches phone code

These cannot be handled by a single field validator.

8. Business Logic Validation

Business rules are application-specific rules beyond data types.

Examples

Username must be unique
Age must be at least 18
Employee ID required for staff
Premium users require payment details

Business rules differ from syntax validation.

9. Validation Order

Pydantic validates data in stages.

General sequence

Receive raw input
Type conversion
Field validation
Model validation
Return validated model
10. Validation Errors

Instead of crashing, Pydantic returns structured validation errors containing

field name
invalid value
expected type
explanation

This greatly improves debugging.

identifies the exact field

prevents partial processing

invalid value

The application assumes incoming data may be incorrect and verifies it before processing.

Benefits
