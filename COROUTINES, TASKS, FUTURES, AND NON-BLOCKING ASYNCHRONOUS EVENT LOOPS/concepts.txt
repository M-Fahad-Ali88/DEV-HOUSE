Task 1: Deep Dive into async and await
Concept

This task helps you understand how asynchronous functions actually work internally.

When you write:

async def fetch():
    await asyncio.sleep(2)

Python does not execute the function immediately.

Instead:

async def creates a Coroutine Object.
The Event Loop starts running the coroutine.
When await is reached, the coroutine pauses.
The Event Loop saves its current state (line number, local variables, stack).
The Event Loop runs another coroutine instead.
When the awaited operation finishes, the paused coroutine resumes exactly where it stopped.

Key Takeaway
async def creates a coroutine object.
await starts the coroutine (if it hasn't started) and pauses it whenever it encounters another await.
await asyncio.sleep() is non-blocking—it pauses only the current coroutine, not the entire thread.
The Event Loop is responsible for suspending and later resuming the coroutine.

Task 3: Inject a Blocking Call and Observe Event Loop Freeze
Concept

This task demonstrates why blocking functions should never be used inside asynchronous code.

Wrong example

time.sleep(5)

or

requests.get(url)

These functions block the entire OS thread.

Since the Event Loop also runs on that thread, every coroutine stops.

Short Summary

Python's asyncio enables asynchronous programming by using coroutines, tasks, futures, and a non-blocking event loop to efficiently handle multiple I/O-bound operations within a single thread. Coroutines created with async def pause at await, allowing the Event Loop to run other ready tasks without blocking. asyncio.create_task() schedules coroutines for concurrent execution, while asyncio.gather() waits until all tasks complete before continuing. Futures represent results that will become available later and are used internally by tasks. A key concept is avoiding blocking calls like time.sleep() or requests.get() inside async code, as they freeze the Event Loop, whereas non-blocking operations such as await asyncio.sleep() keep the application responsive by allowing other tasks to execute concurrently.
