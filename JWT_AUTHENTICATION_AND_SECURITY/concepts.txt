1. Theoretical Focus

You need to understand these three areas:

A. Session-based vs. JWT authentication

Session-based authentication

User logs in.
Server creates a session.
Session ID is stored in a cookie.
Server keeps session state.
Every request uses the session ID to identify the user.

JWT/stateless authentication

User logs in.
Server creates a signed JWT.
Client sends the token with future requests.
Server validates the token instead of storing a login session.
The backend can remain largely stateless.

Typical JWT flow:

Login → Access Token + Refresh Token → Access Token used for API requests → Refresh Token gets a new Access Token

Access token: short-lived and used to access protected routes.

Refresh token: longer-lived and used to obtain a new access token.

2. Password hashing: bcrypt vs Argon2

Never store passwords like:

password123

Instead, store a password hash.

Two important password-hashing algorithms:

bcrypt — deliberately slow and includes a salt, making brute-force attacks harder.
Argon2 — modern password-hashing algorithm designed to be resistant to GPU/parallel attacks and generally preferred for new applications.

The important distinction:

Password hashing is one-way; encryption is reversible.

When a user logs in:

Entered password
       ↓
Hash/verify against stored hash
       ↓
Correct → Login
Wrong   → Reject
3. SQL Injection Prevention

SQL injection happens when user input is directly combined with SQL.

Unsafe idea:

query = f"SELECT * FROM users WHERE username = '{username}'"

If the application treats user input as part of the SQL statement, an attacker may manipulate the query.

With an ORM and parameterized queries, the user input is treated as data, not executable SQL.

For example:

User.query.filter_by(username=username).first()

The ORM handles parameterization for you.

Your security test should demonstrate that malicious input does not become SQL syntax and cannot bypass authentication or expose unintended records.

Important distinction

401 Unauthorized

Usually means:

The request does not have valid authentication credentials.

Examples:

No JWT
Expired JWT
Invalid JWT

403 Forbidden

Usually means:

The user is authenticated, but doesn't have permission to perform this action.

Example:

User = normal_user
Route = admin-only ledger operation
→ 403 Forbidden
