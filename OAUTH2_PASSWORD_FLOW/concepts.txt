OAuth (Open Authorization) is a secure way to allow third-party appslications to access user data without sharing passwords.

why do we need OAuth:
-> Prevent apps from storing passwords
-> Limits what an app can do with your data
-> Supports secure signal sign-on(SSO)

Types of OAuth Token:-
1. Access Token (Short-lived)
2. Refresh Token (Long-Lived)


1. OAUTH2 PASSWORD FLOW

Concept: OAuth2 Password Flow mein user username aur password provide karta hai. Server credentials verify karke ek access token issue karta hai, jise protected API resources access karne ke liye use kiya jata hai.

Example:

Username + Password
        ↓
      /token
        ↓
   Access Token
2. BEARER TOKEN INTEGRATION

Concept: Bearer token ek access token hota hai jo client protected API request ke Authorization header mein Bearer scheme ke saath send karta hai. Server token ko verify karke request allow karta hai.

Example:

GET /profile
Authorization: Bearer eyJhbGciOi...
3. ROUTE-LEVEL SECURITY SCHEMES

Concept: Route-level security mein har API endpoint ke liye specific security requirement define ki ja sakti hai. Isse different routes ko different permissions ya scopes diye ja sakte hain.

Example:

GET  /admin/users
→ admin:read

POST /admin/users
→ admin:write
4. CUSTOM OPENAPI SCHEMA GENERATION

Concept: FastAPI automatically OpenAPI documentation generate karta hai, lekin hum is schema ko customize karke routes ki descriptions, response examples aur tags ko more informative bana sakte hain.

Example:

GET /admin/users

Description:
Retrieve all admin users.

Response:
{
    "count": 2
}

1. OAUTH2 PASSWORD FLOW

Real-world example: GitHub-type application

Tum apne account mein username/password se login karte ho. Server credentials verify karta hai aur successful login ke baad application ko access token milta hai. Phir application us token ko use karke tumhare protected resources access karti hai.

Simple analogy:
Jaise university portal par login karne ke baad tumhein ek authenticated session milta hai, jisse tum apni attendance, grades waghera dekh sakte ho.

2. BEARER TOKEN INTEGRATION

Real-world example: Banking app API

Tum banking application mein login kar chuke ho. Jab app tumhara account balance API se request karti hai, woh har baar password nahi bhejti. Instead, request ke saath access token bhejti hai:

App
 ↓
Bearer Token
 ↓
Bank API
 ↓
Account Balance

Jis system ke paas valid bearer token hai, woh us token ke allowed resources access kar sakta hai.

3. ROUTE-LEVEL SECURITY SCHEMES

Real-world example: Company Admin System

Company ke admin panel mein different actions ke liye different permissions hoti hain:

Employee List dekhna
→ READ permission

Employee create/delete karna
→ WRITE/ADMIN permission

Isliye:

/admin/employees
→ employee:read

/admin/employees/create
→ employee:write

Yani user authenticated hone ke bawajood har route access nahi kar sakta.

Professional API documentation mein developers ko clearly dikhaya jata hai:

We studied this topic because it combines two important real-world API development skills: security and documentation.

1. OAuth2 + Scope-Based Security 🔐

Purpose: control who can access what.

For example, in a real company API:

Normal user → can read their profile
Admin with admin:read → can view administrative data
Admin with admin:write → can create/update administrative data
User without the required scope → gets 403 Forbidden

So you learned how to move from simply saying "user is logged in" to "user is logged in AND has permission for this specific operation."

2. OpenAPI Customization 📚

Purpose: make your API understandable and usable by developers.

FastAPI automatically generates /docs and /redoc, but real projects often need better documentation:

What does this endpoint do?
What permissions are required?
What responses can occur?
What does the JSON response look like?
Which endpoints belong to administration?

You learned how to provide that information using descriptions, tags, summaries, and response examples.
