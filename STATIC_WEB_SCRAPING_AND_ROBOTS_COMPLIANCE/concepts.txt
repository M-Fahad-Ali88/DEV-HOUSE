1. HTTP Request/Response Lifecycle

Jab scraper kisi website ko access karta hai, sabse pehle HTTP request send hoti hai.

Scraper
   ↓
HTTP Request
   ↓
Web Server
   ↓
HTTP Response
   ↓
HTML Document
   ↓
Parser
   ↓
Required Data

Example:

GET https://example.com/stocks

Server response mein HTML bhej sakta hai:

<table>
    <tr>
        <td>AAPL</td>
        <td>245.20</td>
    </tr>
</table>

Scraper ka kaam response se useful information extract karna hota hai.

Important HTTP concepts

Request:

URL
HTTP method
Headers
Optional parameters/body

Response:

Status code
Headers
Response body

Common status codes:

200 → Request successful
301/302 → Redirect
403 → Forbidden
404 → Not Found
429 → Too Many Requests
500 → Server error

Scraper ke liye status code important hai kyun ke parser ko HTML milne se pehle request successful honi chahiye.

1. Scraper

Scraper hamara Python program hai jo website se automatically data lene ke liye banaya gaya hai.

Example:

import requests

url = "https://example.com/stocks"

Yahan Python program decide karta hai:

"Mujhe is website se stock data chahiye."

2. HTTP Request

Scraper website ko ek request bhejta hai.

Scraper
   ↓
"Website, mujhe tumhara page do."

Technically:

GET /stocks HTTP/1.1
Host: example.com

Python mein:

response = requests.get(url)

GET ka matlab basically hai:

Server se resource/data maango.

3. Web Server

Request website ke web server tak jati hai.

Python Scraper
      ↓
Internet
      ↓
Web Server

Server request receive karta hai aur dekhta hai:

"Is URL par kya resource available hai?"

Server phir requested page prepare karta hai.

4. HTTP Response

Server scraper ko response bhejta hai.

Web Server
    ↓
HTTP Response

Response mein different cheezen ho sakti hain:

Status Code
Headers
Body

Example:

HTTP/1.1 200 OK
Content-Type: text/html

200 OK ka matlab:

Request successfully process ho gayi.

5. HTML Document

Response ka body HTML ho sakta hai.

Example:

<html>
    <body>
        <table>
            <tr>
                <td>AAPL</td>
                <td>245.20</td>
            </tr>
        </table>
    </body>

Ab scraper ke paas raw HTML aa gaya.

Important distinction:

HTTP Response
     ↓
Response Body
     ↓
HTML Document
6. Parser

Ab raw HTML ko directly read karna difficult hai.

Isliye hum HTML parser use karte hain.

Tumhare task mein:

BeautifulSoup4

from bs4 import BeautifulSoup

soup = BeautifulSoup(response.text, "html.parser")

BeautifulSoup HTML ko parse karke uska structure samajhne mein help karta hai.

Example:

HTML
 │
 └── table
      │
      └── tr
           ├── td → AAPL
           └── td → 245.20
7. Required Data

Ab parser ke through hum sirf woh information nikalte hain jo humein chahiye.

row = soup.select_one("table tr")

cells = row.select("td")

symbol = cells[0].get_text(strip=True)
price = cells[1].get_text(strip=True)

Result:

Symbol: AAPL
Price: 245.20

Yani required data mil gaya.

2. CSS Selectors vs XPath

HTML ek tree structure hota hai:

HTML
 └── BODY
      └── TABLE
           └── TR
                ├── TD
                └── TD

Humein kisi specific element ko locate karna hota hai.

CSS Selector

Example:

table.stock-data

Ya:

table.stock-data tr

Meaning:

stock-data class wali table ke andar ke rows select karo.

BeautifulSoup CSS selectors ko support karta hai:

soup.select("table.stock-data tr")
XPath

XPath bhi HTML elements locate karne ke liye use hota hai.

Example:

//table[@class='stock-data']//tr

Meaning:

Aisi table find karo jiska class stock-data hai, phir uske andar ke tr elements find karo.

Main Difference
CSS Selector	XPath
Simple aur readable	More powerful/complex
BeautifulSoup mein directly supported	Usually lxml/Selenium etc.
., #, > etc. use karta hai	/, //, @ etc. use karta hai
Static HTML scraping mein convenient	Complex DOM navigation mein useful

Is task mein hum BeautifulSoup + CSS selectors use karenge.

3. Static DOM Parsing

DOM = Document Object Model

Browser HTML ko ek tree-like structure mein represent karta hai.

Example:

<table class="stock-data">
    <tr>
        <td>AAPL</td>
        <td>245.20</td>
    </tr>
</table>

Conceptually:

TABLE
 └── TR
      ├── TD → AAPL
      └── TD → 245.20

BeautifulSoup HTML ko parse karke humein is structure ke elements access karne deta hai.

For example:

soup.select_one("table.stock-data")

Table mil jayegi.

Phir:

table.select("tr")

Rows mil jayengi.

Phir:

row.select("td")

Cells mil jayengi.

Static DOM ka matlab

Static scraping mein hum woh HTML parse karte hain jo HTTP response mein already available ho.

Server
  ↓
HTML
  ↓
BeautifulSoup
  ↓
Data

Agar webpage JavaScript se baad mein data generate karta hai:

Server
  ↓
Initial HTML
  ↓
JavaScript
  ↓
API Request
  ↓
Dynamic Data

to simple BeautifulSoup ko woh dynamically generated data directly nahi mil sakta.

Is task ka focus static DOM hai.

4. Missing Nodes Handling

Real-world HTML perfect nahi hota.

Expected:

<tr>
    <td>AAPL</td>
    <td>Apple</td>
    <td>245.20</td>
</tr>

Lekin kabhi:

<tr>
    <td>AAPL</td>
    <td>Apple</td>
</tr>

Price missing hai.

Agar scraper assume kare:

Column 1
Column 2
Column 3

to error aa sakta hai.

Isliye scraper ko defensive parsing karni chahiye:

Element exists?
      ↓
    Yes → Extract
      ↓
     No → None / default

Goal:

Ek missing field ki wajah se entire scraper crash nahi hona chahiye.

5. Malformed HTML

Web pages hamesha perfectly written nahi hote.

Example:

<tr>
    <td>AAPL
    <td>245.20
</tr>

Yahan <td> properly close nahi kiya gaya.

Parser ko malformed HTML ke saath bhi reasonable structure recover karna hota hai.

BeautifulSoup isi liye useful hai:

Raw HTML
   ↓
BeautifulSoup Parser
   ↓
Parsed DOM
   ↓
Elements
   ↓
Data
6. Ethical Web Scraping

Scraping ka matlab sirf:

"Website se data automatically download karna"

nahi hai.

Responsible scraper ko website ke rules aur server resources ka respect karna chahiye.

Main principles:

robots.txt
    +
Rate Limiting
    +
Respectful User-Agent
    +
Terms of Service
    +
No unauthorized access
7. robots.txt

Websites commonly root level par ye file provide karti hain:

/robots.txt

Example:

User-agent: *
Disallow: /admin/
Disallow: /private/
Allow: /public/

Iska basic purpose crawlers ko batana hai ke website ke kaunse areas crawling ke liye allowed/disallowed hain.

Robots Flow

Humara scraper:

Target URL
    ↓
Find domain
    ↓
robots.txt
    ↓
Check crawling rules
    ↓
Allowed?
   / \
 Yes  No
  ↓    ↓
Request Stop

Yani actual webpage request se pehle compliance check hoga.

8. Rate Limiting

Agar scraper continuously requests bhejta rahe:

Request
Request
Request
Request
Request
Request
...

to server par unnecessary load aa sakta hai.

Responsible scraper:

Request
   ↓
Wait
   ↓
Request
   ↓
Wait
   ↓
Request

Isay rate limiting kehte hain.

Agar server 429 Too Many Requests return kare, scraper ko requests slow/down ya temporarily stop karni chahiye.
